# alpha.4：分组标记与保存栏兼容修正

运行目标：Minecraft Java 1.20.1 / Forge 47.4.0 / Java 17。

## 改动

分组的加号、减号移除黑色矩形底板，只绘制白色符号及黑色字形描边。

经典网格使用每个屏幕处理器自己的 119 格选物库存，不再扩大原版共享的 `CreativeInventoryScreen.INVENTORY`。原版共享库存维持 45 格；背包页、已保存的物品栏使用原版布局。经典取物判断与拖动排除逻辑指向这个独立库存，玩家快捷栏和服务端槽位仍保持原来的编号。

已保存的物品栏复用处理器初始槽位，保留其他模组在创建槽位时加入的行为，不再每次用新的原版槽位替换它们。

切换分类时，在首次填充之前配置目标布局。从经典分类进入已保存的物品栏时，在 Minecraft 读取 `hotbar.nbt` 之前恢复 9 × 5 布局，并释放独立选物库存、分类源列表及折叠列表中的物品引用。退出背包页时，先让原版恢复槽位，再配置目标网格。

保存记录的读取、写入、NBT 格式和数据升级沿用 Minecraft 原来的实现，没有更改或删除用户的保存记录。

## 验证记录

本轮新增测试和结果见 `qa/creative`。测试模组与测试保存记录仅用于开发客户端，不包含在发布 JAR 中。

最终构建在 Forge 开发客户端、集成服务器及独立测试模组中复测通过。客户端堆上限为 1 GiB；测试保存文件含 81 个物品，每个含 128 KiB NBT 测试数据，总载荷 10.125 MiB，文件大小 10,623,829 字节。新客户端从该文件实际读取保存记录。

| 检查 | 结果 |
| --- | --- |
| 构建、Mixin 引用映射、访问转换 | 通过 |
| 原版共享库存容量 | 45 格，不再扩容 |
| 四分类完整性与 12 个模组分类 | 1486 个物品/NBT 身份全部可达 |
| 200 轮与 500 轮连续切页 | 共 700 轮，通过；保存栏的 81 个记录及滚动后的行列/NBT 均正确 |
| 保存栏的原始槽位实例与跟踪列表 | 原始实例保留，槽位与两份跟踪列表均为 54 项 |
| 切换后分类源列表、折叠列表及独立库存 | 旧引用清空 |
| 200 轮回收后的堆占用 | 515.73 → 516.30 MiB |
| 500 轮回收后的堆占用 | 515.39 → 515.91 MiB |
| 鼠标点击保存栏标签、组图标展开与收起 | 通过 |
| 右键取物、两种 NBT 变体、Shift 取物、拖动分配 | 通过 |
| 保存的模组物品取出及快捷栏服务端同步 | 通过，取出物品保留 128 KiB NBT 测试数据 |
| 中文及标签搜索、模组搜索、Forge 分页、小窗口回退 | 通过 |
| 加号与减号显示 | 实际截图确认无矩形黑底，仅保留字形描边 |

原始结果、构建日志及截图位于 `qa/creative/alpha4`。堆使用量是开发环境观测值，不能证明任意模组组合不存在内存问题。

用户报告在模组环境选择已保存的物品栏出现内存耗尽。目前没有取得该环境的崩溃报告、日志或保存记录，无法确认具体抛出位置。这版修正了共享库存扩容和切换时序的兼容性隐患；不能把本地回归通过等同于已经确认修复该整合包的内存问题。若仍出现错误，应依据 `crash-reports` 中的报告与 `logs/latest.log` 的异常堆栈继续定位。
