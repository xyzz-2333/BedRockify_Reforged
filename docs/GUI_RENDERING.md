# GUI 文字绘制约定（1.20.1）

## 浅底文字与重影

书与笔双页的页码曾使用 `drawCenteredTextWithShadow` 和棕色 `0x605444`，与原版黑色、无阴影正文不一致。深色字的偏移阴影在浅色纸张上像重影；改为居中计算坐标后调用 `drawText(..., 0xff000000, false)`。左右页码、原版编辑页正文及另一页的自定义正文均使用黑色无阴影字。

创造物品栏搜索框此前的同类问题涉及另一条路径：`TextFieldWidget` 默认绘制阴影，而且同时自动注册绘制与手动绘制会把文字画两次。现有实现通过 `CreativeSearchStyle` 只标记浅底搜索框；三种文字重载均禁用阴影，保留原版返回坐标额外的一像素，避免光标、选区和中间插字错位。控件使用 `addSelectableChild` 接收输入，由所属界面手动绘制一次。

## 新增或修改文字时

- 浅底面板标题、标签、页码与编辑文字使用 `drawText(..., false)`；颜色明确写成 `0xffRRGGBB`。居中文字自行减去 `textRenderer.getWidth(text) / 2`，不要为方便居中调用带阴影的接口。
- 原版文字移到新位置时，取消原来的那次绘制，或只对原版绘制坐标做一次变换。不得在原文字上叠加新颜色来覆盖；文字的空白像素无法遮住旧字。
- 一个控件只保留一个绘制入口。需要手动绘制时用 `addSelectableChild`，不要再通过 `addDrawableChild` 或 `addDrawable` 自动绘制；保留输入、焦点和旁白事件。
- 批量顶点会使用提交时的着色状态。切换全局 shader 颜色前后使用 `DrawContext.setShaderColor`（内部会先提交），或显式提交后再修改；不能让其他图标的染色影响排队中的文字。矩阵 push/pop 和 scissor 启用/关闭必须配对，局部状态不能泄漏到下个控件。
- 原版 `DrawContext` 在生成字形顶点时已使用当前矩阵；不要把所有问题归因于延迟提交，或为每一个字无条件增加 flush。先确认是否为阴影、重复绘制、字体自身颜色、全局染色或坐标偏移。
- HUD 白字阴影、按钮的原版文字样式、物品数量及分组加减号的黑色描边有各自用途，不全局修改 `TextRenderer`。富文本显式样式也可能覆盖基础颜色，需逐个检查。

## 验证

`gradlew --gradle-user-home .gradle-user runClient -PguiTextClient --offline` 使用书本测试世界运行专用客户端检查。屏幕同时绘制实际书页和原版无阴影参考字，读取实际帧缓冲，逐像素比较左右页码、当前编辑页及另一页的中英文正文，检查偏移阴影与墨色；输出 `book-flat-text.png`。参考字位于书本外，不替换被检区域。测试不提交书本网络包，不修改背包。

创造物品栏布局、搜索输入和界面记忆另用 `-PinventoryUiClient` 检查；双页编辑、翻页、签名和主副手保存另用 `-PsnowBookClient` 检查。测试属性分别使用，不加入正式发布构建。截图、机器路径和本次执行日志保存在 Git 外的 outputs。
