# alpha.6：配方栏恢复与标签图标

Minecraft 1.20.1 / Forge 47.4.0 / Java 17。

## 修正

- 生存背包、工作台的右上角改为独立的配方栏开关。不依赖原版配方书按钮的坐标、渲染与可见性；其他模组隐藏或移除原版按钮后，仍可显示或收起配方栏。按钮的键盘导航和旁白使用 Minecraft 原来的控件行为。
- 只有玩家点击开关才保存配方栏的开闭偏好。其他模组为打开自己的页面而临时调用原版配方书的关闭操作，不再永久覆盖用户的选择。alpha.5 已保存的关闭状态不会强行重置；点击新按钮即可恢复并保存开启状态。
- 自定义配方页仅在当前屏幕确实使用经典布局时接管原版绘制和输入。界面被复用但遗漏初始化时，在绘制前重新准备；从临时页面返回原版回退布局时，恢复背景尺寸与槽位位置。
- 创造分类标签去掉物品图标后额外的一层矩形底色。保留标签边框、选中状态与 Forge 的上下分页栏。配方页分类按钮没有叠加这一层底色。
- 未改动用户截图中由其他模组添加的合成槽按钮。

截图能确认的是右侧经典背包保留、左侧配方栏和恢复按钮不可见；无法仅凭截图确定哪个模组触发了关闭或隐藏。完整的原版 JEI 返回流程会重新初始化屏幕，不能把正常的 JEI 返回单独认定为本次故障根因。

## 验证

生命周期回归脚本：`qa/survival/validate_recovery.py`。它通过独立开发测试模组调用真实客户端屏幕切换、原版配方书状态变化及屏幕点击路径，并验证原版/经典背景尺寸与槽位坐标。

真实 Forge 开发客户端，1280 × 720、GUI 缩放 2、1 GiB 最大堆，同时安装 JEI `15.56.0.205`、Curios `5.14.1+1.20.1` 与开发测试模组。后者注册 900 个物品和 10,900 条配方，其中 10,000 条带独立输出 NBT。测试模组不包含在发布安装包中。

| 检查 | 结果 |
| --- | --- |
| 发布构建、Mixin 引用映射、访问转换 | 通过 |
| 玩家收起/展开后重新打开背包 | 保留用户偏好，新开关可用 |
| 外部临时关闭配方书 | 不覆盖用户偏好，再打开恢复 |
| 原版按钮及自定义按钮从控件列表移除 | 仍能绘制独立开关，点击可以收起和恢复 |
| 临时页面返回；屏幕包装器遗漏初始化 | 经典布局恢复，槽位坐标正确 |
| 返回时关闭经典布局 | 背包与工作台恢复 176 × 166 原版背景，原槽位坐标正确 |
| 真实 JEI 配方页面往返 | 背包、工作台均通过 |
| 实际点击 Curios 饰品按钮及返回按钮 | Curios 保持 48 槽原布局，返回后经典背包与配方栏恢复 |
| 2 × 2 / 3 × 3 原版材料填入、取出、Shift、拖拽、盔甲和副手 | 通过 |
| 中文/标签/无结果搜索与全部 10,000 个配方输出 NBT | 通过，服务器成品 NBT 保留 |
| 小窗口回退和配置切换恢复 | 通过 |
| 开关开启/关闭、创造分类图标的实际截图 | 开关始终可见，标签图标没有额外矩形底色 |

恢复回归包含 32 条实际客户端命令；常规合成回归包含 83 条命令。常规回归的初始状态需要显式启用经典布局，避免此前的回退测试开关影响后续用例。原始记录和截图见 `qa/survival/results/alpha6-*` 与 `qa/survival/images/alpha6-*`。

alpha.5 的压力计时保留在 `ALPHA5.md`，没有在本次重测，不能当作 alpha.6 新测得的计时。用户的完整 158 模组整合包与独立服务器不在本次环境中，仍需用户复测。
